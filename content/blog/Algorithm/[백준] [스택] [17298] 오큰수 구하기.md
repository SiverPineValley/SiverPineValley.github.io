## 1. 문제 소개

> 크기가 N인 수열 $ A = A_1, A_2, ..., A_N $ 이 있다. 수열의 각 원소 $ A_i $ 에 관련된 오큰수 NGE(i)를 구하려고 한다.
> 
> $ A_i $ 의 오큰수는 오른쪽에 있으면서 $ A_i $ 보다 큰 수중 가장 왼쪽에 있는 수를 의미한다. 이런 수가 없을 때 오큰수는 -1이다.
>
> 예를 들어 A = [3,5,2,7]일 때 NGE(1) = 5, NGE(2) = 7, NGE(3) = 7, NGE(4) = -1이다. A=[9,5,4,8]일 때는 NGE(1) = -1, NGE(2) = 8, NGE(3) = 8, NGE(4) = -1이다.
>
> 입력: 1번째 줄에 수열 A의 크기 N(1 <= N <= 1,000,000), 2번째 줄에 수열 A의 원소 $ A_1,A_2,...,A_N (1<=A_i<=1,000,000) $ 이 주어진다.
>
> 출력: 총 N개의 수 NGE(1),NGE(2),...,NGE(N)을 공백으로 구분해 출력한다.

## 2. 나의 접근법

처음에는 각 단계의 수와 스택의 top을 비교하고, 스택 top의 수보다 지금 수가 크면 top을 빼고 현재 수를 오큰수로 지정하고, 아니면 현재 수를 추가로 넣는 방식을 생각했는데, 이 경우 스택의 구조 상 후입 선출되면서 순서가 뒤바뀌어버리게 된다는 것을 알게 되었다. 따라서 큐를 사용해야 하나 싶었는데, 큐를 쓰면 선입 선출 방식은 유지되지만, 최악의 경우 모든 케이스를 비교하게 된다는 단점이 있었다. 입력되는 수열의 최대 크기가 1,000,000건 이므로, $Θ(n^2)$의 시간 복잡도로 구현하면 실패할 수 밖에 없는 케이스가 되므로, 큐는 방법이 아니라고 생각했다.

그런데 생각해보니 스택에 그 수를 넣는게 아니라, 그 수의 index를 넣는다면 순서가 뒤바뀌어도 상관 없이 수열의 순서에 맞는 오큰수를 찾아낼 수 있겠다 싶었고, 이 방법으로 구현을 해보았다.

1. 변수 초기화. 오큰수열은 -1로 초기화
2. 스택이 채워져 있고, 스택의 top의 index 수열과 현재 수열 값 비교해서, 현재 값이 클 때 (반복)
    2-1. 스택 top을 pop하고, 현재 수열 값을 오큰수로 기록
3. 현재 수열 값 index를 stack에 push
4. 오큰수열 출력

```python3
"""
    [17298] 오큰수 구하기
    링크: https://www.acmicpc.net/problem/17298
    카테고리: 자료구조 > 스택
    날짜: 2026.08.23 14:40PM
    걸린 시간: 50분
"""
import sys

N = int(sys.stdin.readline())
A = list(map(int, sys.stdin.readline().split()))
NGE = [-1] * N
stack = []

for i in range(N):
    while stack and A[stack[-1]] < A[i]:
        tIdx = stack.pop(-1)
        NGE[tIdx] = A[i]
    stack.append(i)

for a in NGE:
    print(a, end=' ')
print()
```

이와 같이 풀어도 정답은 맞긴 하지만, pop() => 기본값이 맨 뒤 (-1) 요소를 빼는 것이므로 생략하는 것이 더 간결한 점이 있었고, 출력시 언팩(Unpacking) 연산자를 사용하면 리스트나 딕셔너리를 보다 간결하게 출력하는게 가능하므로, 언팩 연산자를 사용하는 방식으로 개선하였다.


```python3
"""
    [17298] 오큰수 구하기
    링크: https://www.acmicpc.net/problem/17298
    카테고리: 자료구조 > 스택
    날짜: 2026.08.23 14:40PM
    걸린 시간: 50분
"""
import sys

N = int(sys.stdin.readline())
A = list(map(int, sys.stdin.readline().split()))
NGE = [-1] * N
stack = []

for i in range(N):
    while stack and A[stack[-1]] < A[i]:
        NGE[stack.pop()] = A[i]
    stack.append(i)

print(*NGE)
```

## 3. 경계값 테스트

### 3-1. 최소 입력 크기 (N = 1)
                                               
• 입력:
1
5

• 출력: -1

### 3-2. 원소 값의 경계값 (Aᵢ = 1 및 Aᵢ = 1,000,000)
• 입력:
2
1 1000000

• 출력:
1000000 -1

• 의미: 최소값/최대값 처리 시 정수 범위 문제나 조건식 오류가 없는지 확인합니다.

### 3-3. 모든 원소가 동일한 경우

• 입력:
5
7 7 7 7 7

• 출력: -1 -1 -1 -1 -1
• 의미: 오큰수는 자신보다 엄격히 큰(strictly greater) 수여야 하므로, 같은 수는 오큰수가 될 수 없습니다 (A[stack[-1]] < A[i] 조건 검증).

### 3-4. 엄격한 오름차순

• 입력:
5
1 2 3 4 5

• 출력: 2 3 4 5 -1
• 의미: 스택이 깊어지지 않고 매번 즉시 pop되는 케이스입니다.

### 3-5. 엄격한 내림차순

• 입력:
5
5 4 3 2 1

• 출력: -1 -1 -1 -1 -1
• 의미: 모든 원소가 스택에 끝까지 쌓여 있다가 한 번도 오큰수를 만나지 못하고 끝나는 케이스입니다.


### 3-6. 스택 연속 연산 및 메모리 최악 케이스 (V자 형태 구조)

• 입력 예시 (N = 1,000,000):
1000000
1000000 999999 999998 ... 3 2 1 1000001

• 특징 및 이유:
    1. N - 1번째 원소까지 계속 값이 감소하므로 오큰수를 찾지 못해 스택 크기가 N - 1까지 비대해집니다. (스택 메모리 사용량 극대화)
    2. 마지막 N번째 원소에서 매우 큰 수가 입력되는 순간, while 루프가 연속 N - 1번 한 번에 폭발적으로 실행되면서 모든 스택 요소를 pop합니다.
    3. 분할 상쇄(Amortized) 분석으로 전체 시간 복잡도는 여전히 O(N)이지만, 순간적인 스택 메모리와 연속 pop 연산 횟수가 가장 높은 케이스입니다.

#### 3-7. 입출력(I/O) 및 파이썬 파싱 최악 케이스

• 입력 예시:
    • N = 1,000,000 이며, 모든 Aᵢ가 1,000,000 근처의 7자리 숫자인 경우.
• 특징 및 이유:
    • 입력되는 텍스트 용량만 약 8MB, 출력되는 텍스트 용량도 8MB에 달합니다.
    • 파이썬에서는 1,000,000개의 정수 객체를 생성하고 문자열 파싱/출력하는 부하가 극대화되므로, 빠른 입출력(sys.stdin.readline 및 print(*NGE))을 쓰지 않으면 시간 초과가 발생하기    
    가장 쉬운 케이스입니다.
